## 1. 系统概述

### 1.1 能做什么

| 页面 | 路由 | 主要能力 |
|---|---|---|
| 运行总览 | `#/` | 状态、模型信息、24 小时报警统计（按小时趋势 / 按来源占比） |
| 实时检测 | `#/live` | 调用本机摄像头，逐帧推理并叠加检测框，实时告警 |
| 图片检测 | `#/image` | 上传单张图片，查看检测框、置信度与告警结论 |
| 视频检测 | `#/video` | 上传视频文件，后台逐帧检测，产出标注视频与汇总 |
| 报警记录 | `#/events` | 历史报警分页、筛选、快照查看与删除 |
| 参数设置 | `#/settings` | 模型切换、推理阈值、告警策略、数据维护 |

### 1.2 界面总览

页面顶部为**主导航**，从左到右依次是：**总览 / 实时检测 / 图片检测 / 视频检测 / 报警记录 / 参数设置**。
右上角有两个状态控件：

- **响铃**：告警提示音开关，点击可在「响铃开 / 静音」之间切换。
- **已连接 / 未连接**：后端连接状态。显示「已连接」表示后端 `127.0.0.1:8000` 正常可用。
  若显示「后端未连接」，页面会给出启动命令提示（详见 [第 6 节](#6-常见问题排查faq)）。

各页面标题右侧会显示**当前模型名**（如 `fire-smoke-yolov8n`）与**推理设备**（如 `GPU #0`），
方便一眼确认运行配置。页面底部状态栏显示版本号与运行时长。

### 1.3 关键概念

| 概念 | 说明 |
|---|---|
| **置信度 conf** | 模型对某个检测框的把握程度，取值 0~1，界面以百分比显示（如 76%）。 |
| **阈值 conf_thres** | 低于该置信度的检测框会被丢弃，**默认 0.25**。 |
| **告警阈值 alarm_conf** | 只有置信度 ≥ 该值的框才可能写入报警记录，**默认 0.50**。 |
| **连续命中帧数 alarm_consecutive** | 连续多少帧命中才告警（防抖），**默认 3**，仅摄像头实时流生效。 |
| **告警冷却 cooldown** | 同一路画面在冷却时间内最多产生一条记录，**默认 20 秒**。 |
| **xyxy** | 检测框的**像素坐标**（相对原图左上角）。 |
| **xyxyn** | 检测框的**归一化坐标**（0~1），实时叠加框统一使用它，与分辨率无关。 |
| **告警等级** | `none`（无） / `warning`（烟雾） / `critical`（火焰）。 |

## 2. 运行环境准备

### 2.1 前置要求

- **Python 3.10+**（本项目在 3.13.9 上验证）
- **Node.js 18+**（本项目在 v24.10.0 上验证）
- 可选：**NVIDIA GPU + 驱动**（本项目在 RTX 4070 Laptop / CUDA 12.4 跑通；**无 GPU 会自动回退 CPU**）

### 2.2 安装后端（虚拟环境）

所有 Python 依赖都装在项目根目录的 `.venv` 里，**请勿使用系统全局 Python**。

```bash
# ① 在项目根目录创建虚拟环境
python -m venv .venv

# ② 安装 CUDA 版 PyTorch（无 GPU 可跳过，直接执行第 ③ 步装 CPU 轮子）
.venv/Scripts/python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124

# ③ 安装其余依赖
cd backend
../.venv/Scripts/python.exe -m pip install -r requirements.txt
```

> macOS / Linux 把 `.venv/Scripts/python.exe` 换成 `.venv/bin/python`。

### 2.3 下载模型权重

> ! 权重文件（`backend/weights/*.pt`）**不随代码库分发**，必须自行下载。

```bash
cd backend
../.venv/Scripts/python.exe scripts/download_weights.py --list     # 查看当前状态（是否已下载）
../.venv/Scripts/python.exe scripts/download_weights.py --verify   # 下载并校验类别
```

脚本会打印权重的**真实类别名**，确认是 `['fire', 'smoke']` 二类即成功。可选模型：

| 注册名 | 大小 | 类别 | 定位 |
|---|---|---|---|
| `fire-smoke-yolov8n` | 约 6.0 MB | fire / smoke | 轻量，**实时首选**（默认） |
| `fire-smoke-yolov8s` | 约 21.5 MB | fire / smoke | 高精度，速度略慢 |

### 2.4 安装前端

前端依赖只有 `vue` / `vue-router` / `vite` / `@vitejs/plugin-vue`，**无任何 UI 组件库**。

```bash
cd frontend
npm install
```

## 3. 启动、验证与停止服务

> 正常运行需要**同时开启两个服务**：后端（8000）与前端（5173）。
> 建议分别放在**两个终端窗口**里，或作为后台托管进程运行。

### 3.1 启动后端（端口 8000）

```bash
cd backend
../.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 即启动成功。
模型加载失败**不会**阻塞服务启动，前端会在参数设置页给出提示。

### 3.2 启动前端（端口 5173）

```bash
cd frontend
npm run dev
```

看到 `Local: http://127.0.0.1:5173/` 即启动成功。
开发模式下 Vite 会把 `/api`、`/static`、`/ws` 自动代理到 `http://127.0.0.1:8000`。

### 3.3 验证服务是否正常

用浏览器打开 <http://127.0.0.1:5173>，页面右上角应显示 **「已连接」**。
也可用命令行快速核对（无需打开浏览器）：

```bash
# 后端健康检查：应返回 status=ok、model_loaded=true
curl -s http://127.0.0.1:8000/api/health

# 后端配置：conf_thres 应为 0.25
curl -s http://127.0.0.1:8000/api/config

# 前端首页：应返回 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:5173/
```

实测参考输出：

```json
/api/health → {"status":"ok","version":"1.0.0","uptime_sec":221.6,"model_loaded":true,"device":"cuda:0"}
/api/config → {"conf_thres":0.25,"iou_thres":0.45,"imgsz":640,"device":"auto","alarm_conf":0.5,
               "alarm_consecutive":3,"alarm_cooldown_sec":20,"save_snapshots":true,
               "max_upload_mb":50,"model":"fire-smoke-yolov8n"}
```

### 3.4 停止服务

在对应终端窗口按 **`Ctrl + C`** 即可停止。
若使用的是后台托管进程（如 IDE / 任务面板里的进程），直接点「停止」即可。

### 3.5 重启服务

```text
① 停止正在运行的后端与前端进程；
② 按 3.1 / 3.2 重新启动后端与前端；
③ 按 3.3 验证 /api/config 返回 conf_thres=0.25、前端首页返回 200。
```

> 重启后端会**丢失未完成的视频检测任务**（任务是进程内后台线程）。

**端口被占用（Windows `[Errno 10048]`）排查**：

```bash
# 查出占用 8000 端口的进程号
netstat -ano | grep ':8000' | grep LISTENING

# 强制结束该进程（把 <PID> 换成上一步查到的进程号）
taskkill //F //T //PID <PID>
```

> 常见现象：旧的后端进程没退干净会继续占用 8000，导致新配置不生效（仍返回旧阈值）。
> 遇到「改了参数不生效」时，先按上面步骤确认端口上只有**一个**进程。

## 4. 页面操作指南

### 4.1 运行总览（`#/`）

**用途**：一屏掌握系统状态与 24 小时报警概况。

**操作步骤**

1. 点击顶部导航 **「总览」**。
2. 等待约 1~2 秒加载完成（「更新于」会显示最近刷新时间）。

**界面说明**

- **顶部 KPI 卡片**（5 张）：报警总数 · 24H、火焰告警、烟雾告警、严重级别、最近 1 小时。
- **小时报警趋势**：**手写 SVG 柱状图**，横轴为最近 24 小时，红柱=火焰、灰柱=烟雾；下方给出窗口总数与峰值。
- **报警来源占比**：**手写 SVG 环形图**，按接入方式（图片 / 视频 / 摄像头实时）统计。
- **系统与模型**：后端状态、运行时长、当前模型、推理设备、输入尺寸、权重体积、可用类别、接口版本。
- **最近一次报警**：显示最新一条告警的等级、类别、来源、时间、置信度与快照。

**实测示例**

```text
报警总数·24H = 44 ；火焰告警 = 44 ；烟雾告警 = 0 ；严重级别 = 44 ；最近 1 小时 = 4
来源占比：图片检测 33 条（75.0%） / 视频检测 6 条（13.6%） / 摄像头实时 5 条（11.4%）
最近一次报警：严重 · 火焰 · 视频 · 09-18 10:08:45「检测到火焰」最高置信度 80%
```

> 若从未产生过告警，图表区域会显示**空状态**（「暂无报警数据」），不会有占位假数据。

### 4.2 实时检测（`#/live`）

**用途**：调用本机摄像头做**逐帧实时检测**，画面在浏览器与后端之间传输。

**操作步骤**

1. 点击顶部导航 **「实时检测」**。
2. 点击 **「开启摄像头」**，在浏览器弹窗中**允许**摄像头权限。
3. 摄像头下拉框选择设备（默认「默认设备」，本机实测识别到 `Integrated Camera (30c9:00a6)`）。
4. 点击 **「开始检测」**，画面开始按帧推理。
5. 结束时可点击 **「停止检测」**（或再次点「开启摄像头」）释放摄像头。

**界面说明**

- 视频画面左上角叠加实时参数：**FPS / 推理耗时 / 分辨率**。
- 右侧参数：摄像头、置信度阈值（默认 0.25）、NMS IOU（默认 0.45）、画面质量、是否显示服务端标注图。
- **本帧检测结果**：当前帧的目标列表（类别 / 置信度 / 检测框）。
- **实时统计**（本会话累计）：接收帧数、火焰命中帧、烟雾命中帧、告警次数、最高置信度、当前设备、模型、会话编号。

**实测示例**

```text
设备：Integrated Camera (30c9:00a6)
状态：连接中 · 推理中　FPS：25.2　推理：8.7 ms　分辨率：960×540
接收帧数：158（另一次会话 136）　火焰命中帧：0　烟雾命中帧：0　告警次数：0
会话编号：ws_7ab017a5　当前设备：cuda:0
```

> **无实体火源时命中帧为 0 属正常**：对着普通办公场景拍摄，模型不会误报，说明低误报策略生效。

**告警判定（实时流专有）**：需**连续 `alarm_consecutive`（默认 3）帧**命中且置信度 ≥ `alarm_conf`（默认 0.50），
且在冷却时间内不重复记录，才会写入一条 `camera` 来源的报警记录。

### 4.3 图片检测（`#/image`）★ 重点

**用途**：上传单张图片做检测，查看检测框、置信度与告警结论。

#### 操作步骤（完整流程）

1. 点击顶部导航 **「图片检测」**。
2. **选择图片**：把图片**拖拽**到虚线框内，或点击 **「选择图片」** 从本地选择。
   支持格式：`jpg / png / webp / bmp`。选择成功后右侧会显示文件名与大小（实测如 `manual_fire.jpg · 134.1 KB`）。
3. （可选）调整 **置信度阈值**（默认 0.25）与 **NMS IOU**（默认 0.45）。
4. 保持勾选 **「返回服务端标注图」**（默认开启），可直观看到检测框绘制效果。
5. 点击 **「开始检测」**，等待约 0.1~0.3 秒出结果。
6. 结果面板出现在图片下方；可用 **「换一张」** 重新选择、**「下载标注图」** 保存标注结果、**「清空」** 复位。

#### 结果字段解释

| 字段 | 含义 | 示例 |
|---|---|---|
| 结论徽标 | 告警等级：**正常 / 警告 / 严重** | 严重 |
| 目标总数 | 检出的目标个数 | 1 |
| 火焰 / 烟雾 | 各分类目标数量 | 火焰 1 / 烟雾 0 |
| 最高置信度 | 所有目标中最高的置信度 | 76% |
| 图片尺寸 | 原图宽 × 高（像素） | 960×1280 |
| 推理设备 | 实际使用的设备 | cuda:0 |
| 预处理 / 推理耗时 / 后处理 | 三段耗时（毫秒） | 4.4 ms / 174.3 ms / 2.7 ms |
| 检测编号 | 本次检测的唯一 ID，可用于排查 | `img_20260918_100824_a80117` |
| 目标清单 | 每个目标一行：**类别 · 置信度 · 像素框 XYXY · 归一化框 XYXYN** | 见下 |

**实测示例 A —— 火焰图片（会告警）**

```text
结论：严重（critical）　目标总数 1　火焰 1　烟雾 0　最高置信度 76%
图片尺寸 960×1280　推理设备 cuda:0　预处理 4.4 ms / 推理 174.3 ms / 后处理 2.7 ms
检测编号 img_20260918_100824_a80117　提示：检测到火焰（critical）
目标清单：
  火焰  76%  像素框 XYXY 344, 177, 691, 908   归一化框 XYXYN 0.359, 0.139, 0.720, 0.709
```

**实测示例 B —— 烟雾图片（只显示、不告警）**

```text
结论：正常　目标总数 1　火焰 0　烟雾 1　最高置信度 35%
图片尺寸 960×720　推理设备 cuda:0　预处理 3.6 ms / 推理 127.0 ms / 后处理 1.8 ms
检测编号 img_20260918_100837_aed1ad
目标清单：
  烟雾  35%  像素框 XYXY 57, 169, 576, 416    归一化框 XYXYN 0.060, 0.235, 0.600, 0.578
```

> 注意示例 B：烟雾被检出（35%），但结论是 **「正常」**，**不产生报警记录**。
> 原因见 [第 5 节](#5-阈值与告警策略说明)：35% < 告警阈值 50%。

### 4.4 视频检测（`#/video`）

**用途**：上传视频文件，后台逐帧检测，产出**标注后的视频**并可播放，附带汇总统计。

**操作步骤**

1. 点击顶部导航 **「视频检测」**。
2. 点击 **「选择视频」** 或拖拽视频文件到虚线框。支持格式：`mp4 / avi / mov / mkv`。
3. （可选）调整 **置信度阈值**（默认 0.25）、**NMS IOU**（默认 0.45）、**抽帧步长**
   （默认「每 2 帧」；可选 1 最精细 / 3 / 5 最快）。
4. 点击 **「开始检测」**，下方出现**进度条**（百分比、帧数、FPS）；处理期间按钮变为 **「取消任务」**。
5. 处理完成后：左侧播放器可播放标注视频（提示「已生成标注视频，可直接在左侧播放」），
   右侧显示**任务汇总**，底部「历史任务」表新增一行。

**界面说明**

- **任务进度**：进度百分比、已完成帧数 / 总帧数、处理 FPS。
- **任务信息**：任务编号、文件名、开始时间、结束时间。
- **任务汇总**：检出的目标、火焰帧、烟雾帧、生成报警。
- **历史任务**：文件、状态、进度、帧数、开始时间；点「查看」可回看某个任务。

**实测示例**（测试视频 `fire_test.mp4`，40 帧）

```text
任务编号 vid_20260918_100845_ac4dd5　文件名 fire_test.mp4
开始 09-18 10:08:45　结束 09-18 10:08:46　已完成 100%　40 / 40 帧　63.2 FPS
检出的目标 21　火焰帧 21　烟雾帧 0　生成报警 1
```

> 视频任务的汇总**只统计"帧-level"命中**；告警记录按**冷却时间**聚合，因此「火焰帧 21」通常只生成 **1** 条报警。

### 4.5 报警记录（`#/events`）

**用途**：查看、筛选、删除历史报警。

**操作步骤**

1. 点击顶部导航 **「报警记录」**。
2. 使用顶部 **筛选条件**：**级别**（全部 / 严重 / 警告）、**来源**（全部 / 摄像头 / 图片 / 视频）、
   **类别**（全部 / 火焰 / 烟雾）、**每页**（20 / 50 / 100）。
3. 点击 **「重置筛选」** 可恢复默认；右侧显示「共 N 条记录」。
4. 列表中每行可点击 **「报警快照」** 查看当时画面，或点 **「删除」** 删除单条。
5. 点击 **「清空全部」** 可删除所有报警记录（**不可撤销**，会二次确认）。

**表格列**：时间 / 级别 / 类别 / 来源 / 置信度 / 计数（火 x / 烟 y）/ 说明 / 快照 / 删除。

**实测示例**

```text
共 44 条记录，第 1 / 1 页 · 显示 1–44
09-18 10:08:45  严重  火焰  视频     80%  火 1 / 烟 0  检测到火焰
09-18 10:08:24  严重  火焰  图片     76%  火 1 / 烟 0  检测到火焰
09-18 10:07:13  严重  火焰  视频     80%  火 1 / 烟 0  检测到火焰
09-11 11:57:51  严重  火焰  摄像头   80%  火 1 / 烟 0  连续 3 帧检测到火焰
```

> 注意「说明」列：图片/视频来源显示「检测到火焰」，摄像头来源显示「连续 3 帧检测到火焰」，
> 体现实时流特有的**连击判定**。

### 4.6 参数设置（`#/settings`）

**用途**：切换模型、调整推理阈值与告警策略、维护数据。

**操作步骤**

1. 点击顶部导航 **「参数设置」**。
2. **模型选择**：在 `YOLOv8n`（轻量）与 `YOLOv8s`（高精度）之间单选，
   点击 **「切换模型」** 生效（切换后立即重载，约 1~5 秒）。
3. **推理参数**：拖动 **置信度阈值 CONF_THRES**（默认 25%）、**NMS IOU 阈值**（默认 45%），
   选择 **推理尺寸 IMGSZ**（默认 640 px）、**推理设备 DEVICE**（默认 auto）。
4. **告警策略**：**告警置信度 ALARM_CONF**（默认 50%）、**连续命中帧数**（默认 3）、
   **告警冷却（秒）**（默认 20）、**单文件上传上限（MB）**（默认 50）、是否 **保存报警快照**。
5. **告警提示音**：勾选「响铃开启」，可点 **「试听提示音」** 试听。
6. 修改后底部出现 **「还原」** / **「保存参数」** 按钮（未改动时为禁用，并有「参数与后端一致」提示）；
   点 **「保存参数」** 写入后端并生效。
7. **数据维护**：点 **「清空记录」** 删除所有历史报警与统计（**不可撤销**）。

**运行状态区**：服务状态（在线）、模型状态（已加载）、推理设备、推理尺寸、加载时间、权重文件、可用类别；
右上「刷新」按钮可手动刷新。

> 修改 **device / imgsz / model** 会触发模型重载，请等待切换完成后再进行检测。

**实测示例**

```text
模型：fire-smoke-yolov8n（使用中，5.97 MB）　推理设备：NVIDIA GeForce RTX 4070 Laptop GPU
置信度阈值 CONF_THRES = 25.0%　NMS IOU = 45.0%　推理尺寸 = 640 px　推理设备 = auto
告警置信度 ALARM_CONF = 50.0%　连续命中帧数 = 3　告警冷却 = 20 秒　单文件上限 = 50 MB
```

## 5. 阈值与告警策略说明

### 5.1 两级阈值：显示阈值 vs 告警阈值

系统对「显示」和「告警」使用**两个不同的阈值**，这是理解行为的关键：

```text
   置信度 conf
      ▲
      │
 1.0  │
      │      ┌──────────── alarm_conf = 0.50 ────────────┐   ← 达到此线才"写报警记录"
 0.5  │ ─────┼─────────────── 告警阈值 ──────────────────┤
      │  ✅  │  火焰通常落在这里（0.60~0.90）→ 触发 critical
      │      │  烟雾通常落在这里以下
 0.25 │ ─────┼─────────────── conf_thres 显示阈值 ────────┤   ← 达到此线才"显示检测框"
      │  ⬜  │  烟雾常在 0.17~0.35 → 多数可见，少数低于 0.25 不显示
 0.0  │      │
```

- **`conf_thres = 0.25`（显示阈值）**：低于它的框直接丢弃。调低它能让更多（低置信度）的烟雾框**显示**出来。
- **`alarm_conf = 0.50`（告警阈值）**：只有置信度 ≥ 它的框才可能写入报警记录。

### 5.2 为什么「烟雾只显示、不告警」

公开的火焰/烟雾权重以**火焰样本为主**，对**烟雾**的置信度普遍偏低（实测多在 **0.17~0.35**）。因此：

- 烟雾框的分数通常 **≥ 0.25 但 < 0.50** ⇒ **能显示框**，但**不写告警记录**；
- 火焰框的分数通常 **0.60~0.90** ⇒ 既显示，又触发 **critical 严重告警**。

这正是本系统「**烟雾可见 + 告警低误报**」的默认设计。实测中：图片烟雾检测结论为「正常」、总览烟雾告警数 = 0，
视频里 21 个火焰帧只生成 1 条聚合告警——都属于**预期行为**，不是故障。

> 如需改变这一行为（例如让烟雾也告警），可在**参数设置**里下调 **ALARM_CONF**；
> 但请注意这会**显著增加误报**。若只是想让更多烟雾被检出，可下调 **CONF_THRES**。

### 5.3 默认参数一览

| 参数 | 默认值 | 作用 |
|---|---|---|
| `conf_thres` | 0.25 | 置信度阈值（低于则丢弃检测框） |
| `iou_thres` | 0.45 | NMS IOU 阈值（重叠框去重） |
| `imgsz` | 640 | 推理尺寸（需为 32 的倍数） |
| `device` | auto | 推理设备（有 CUDA 用 GPU，否则 CPU） |
| `alarm_conf` | 0.50 | 告警置信度阈值 |
| `alarm_consecutive` | 3 | 连续命中帧数（仅摄像头实时流） |
| `alarm_cooldown_sec` | 20 | 告警冷却时间（秒） |
| `max_upload_mb` | 50 | 单文件上传上限（MB） |
| `save_snapshots` | true | 是否保存报警快照 |

## 6. 常见问题排查（FAQ）

### Q1：页面右上角显示「后端未连接」

- 确认后端已在 `127.0.0.1:8000` 运行（见 [3.1](#31-启动后端端口-8000)）。
- 开发环境请用 `npm run dev` 打开页面，**不要**用 `file://` 直接打开 `index.html`（代理不生效）。

### Q2：启动后端报 `[Errno 10048] error while attempting to bind on address ('127.0.0.1', 8000)`

端口被占用。按 [3.5](#35-重启服务) 的步骤查出并结束旧进程：

```bash
netstat -ano | grep ':8000' | grep LISTENING
taskkill //F //T //PID <PID>
```

### Q3：改了参数但检测结果没变化

多半是**旧后端进程还在占用 8000**，页面上看到的仍是旧配置。用 Q2 的方法确认端口上只有**一个**进程后重启。

### Q4：摄像头打不开 / 画面黑屏

- 浏览器需**授权摄像头**；`getUserMedia` 只在 `localhost` 或 HTTPS 下可用（`127.0.0.1` 属于安全上下文，无需 HTTPS）。
- 若设备被其他程序（会议软件、相机 App）占用，先释放再重试。
- 下拉框里应先出现设备名（如 `Integrated Camera (30c9:00a6)`）再点「开始检测」。

### Q5：对着真实场景检测，命中帧一直是 0

这是**正常**的：室内普通画面不含火焰/烟雾，模型不会误报，正好说明低误报策略生效。
想看命中效果，请用含火焰/烟雾的**图片或视频**做检测。

### Q6：烟雾明明看得见，却没有报警记录

这是**预期行为**，见 [5.2](#52-为什么烟雾只显示不告警)。烟雾置信度一般低于告警阈值 0.50，只显示不告警。

### Q7：权重加载报 `dill` 相关错误

旧版 Ultralytics 保存的公开权重需要 `dill` 反序列化。`requirements.txt` 已包含 `dill>=0.3.8`，
若仍报错，手动补装：`../.venv/Scripts/python.exe -m pip install dill`。

### Q8：没有 GPU，或在 CPU 上跑很慢

不装 CUDA 版 torch 也能运行（自动回退 CPU，速度下降）。可在参数设置里把 **device** 改为 `cpu`，
或使用更小的推理尺寸（如 416 / 320）。

### Q9：上传文件失败，返回 413

文件超过了 **单文件上传上限**（默认 50 MB）。请压缩文件，或在参数设置里调大「单文件上传上限（MB）」。

### Q10：重启后端后，之前的视频任务不见了

视频任务是**进程内后台线程**（非分布式队列），重启后端会丢失**未完成**的任务；
**已完成**的任务与标注视频、报警记录都会保留（存于 `backend/data/`）。


- 交互式接口文档：<http://127.0.0.1:8000/docs>
- 时间字段统一为 **ISO 8601 带时区**（如 `2026-09-18T10:08:45+08:00`）。
- 坐标：`xyxy` 为像素坐标，`xyxyn` 为 0~1 归一化坐标。
- 静态资源：`/static/snapshots`、`/static/videos`、`/static/uploads`。

### 7.2 数据与文件位置

| 内容 | 位置 |
|---|---|
| 报警记录 | `backend/data/events.db`（SQLite 单文件） |
| 报警快照 | `backend/data/snapshots/` |
| 上传的图片 | `backend/data/uploads/` |
| 标注后的视频 | `backend/data/videos/` |
| 模型权重 | `backend/weights/*.pt`（**不入版本库**） |
| 前端构建产物 | `frontend/dist/`（`npm run build` 生成） |

### 7.3 一分钟上手清单

1. `python -m venv .venv` → 装依赖 → `download_weights.py --verify` → `npm install`。
2. 后端：`cd backend && ../.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000`。
3. 前端：`cd frontend && npm run dev`。
4. 浏览器打开 <http://127.0.0.1:5173>，确认右上角「已连接」。
5. 「图片检测」上传一张火焰图 → 看到红色 FIRE 框、置信度与 `critical` 结论。
6. 「实时检测」授权摄像头 → 看到 FPS / 推理耗时与实时叠加框。
7. 「总览」与「报警记录」核对统计与历史。
